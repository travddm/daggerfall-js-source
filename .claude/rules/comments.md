# Code comments

The base rules are in `docs/README.md` ("Code comments"). This page adds what they leave open. It applies to every
file you create, and to the code you change in an old file.

## What a comment holds

A comment says why: the reason for the code, an invariant, a workaround, a constraint or a trap the code cannot show.
The code says what. Delete a comment that only restates the code.

A departure from Daggerfall Unity is named in a comment where it is made, with its case (online or better design), as
`docs/README.md` ("Scope") asks. Keep those, in plain words.

## What a comment never holds

- Ticket, slice, audit or report codes: `AUDIT SLAM`, `SAFE8:`, `HARD3 -`, `FB1019F`, `(LOOT-GATE)`.
- Dates, release or relay version names of the past, and the names of people who asked for a change.
- History: what the code did before, where it moved from, which pull request or audit changed it.
- Quotes of chat or of people, such as `(mob, 03:03Z: "...")`.
- Banner bars (`// ═══`) and ALL-CAPS headlines. Where a section heading helps, write one plain line in sentence case.
- Cites of `bible/`. That tree was deleted. Cite a `docs/` page, or a file and a function.
- Line numbers. Name a file and a function.

History belongs in git: the commit message and the pull request description.

## Touched code

When you change code, bring the comments of the lines and the function you change to these rules. Do not rewrite the
rest of an old file in the same change: a whole-file comment cleanup is a pull request of its own, done with the
`comment-cleanup` agent (`.claude/agents/comment-cleanup.md`).

## Comments that something reads

Some comment text is read by a test, a tool or the compiler. Leave it as it is unless you change the reader too.

- Every file in the relay's import graph (`graph('server/src/index.js')`, `test/importGraph.mjs`).
  `test/net/relayversion.test.js` hashes those files byte for byte, comments included, so an edit there needs a new
  `RELAY_VERSION`. Clean those comments only in a change that bumps the relay for another reason.
- JSDoc types and tags (`@type`, `@param`, `@returns`, `@typedef`, `@ts-check`): `npm run types` reads them. You may
  reword the prose after a tag.
- Directives: `eslint-disable`, `@ts-expect-error`, `@ts-ignore`, `prettier-ignore`, `/* global */`, `#!`.
- A generated file's header (`// GENERATED by tools/...`). Change the tool that writes it, then run the tool.
- License and attribution headers. Keep them word for word.
- Text a test or a tool quotes. Before you change a comment, search `test/`, `tools/`, `scripts/` and `.github/` for
  the file's path and for the comment's words.

## Prose

Write as `docs/coding-standards.md` ("Documentation") asks: short sentences in the active voice, one term for one
concept, `must`, `should` and `may` for required, recommended and permitted. Do not use em dashes or stock phrases
such as "it is worth noting".
